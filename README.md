## centific 分支里有什么

一个翻译行业的 AI 后编辑平台：上游推入机器译文，平台逐段调用模型
判断「保留还是重译」，翻译人员从逐句改写转为抽查复核。
运行规模是数十个 program、数百个语言对，每个语言对绑定各自的
风格指南与术语表。

技术栈：Python / 消息队列（三队列流水线）/ 双数据库后端 /
容器化部署 / 按队列积压量弹性伸缩。

**值得看的三个文件**：

- [`docs/INCIDENTS.md`](../../blob/centific/docs/INCIDENTS.md) ——
  三次线上事故的完整复盘。这三个问题的共同点是：
  代码没写错，是**设计层面的缺陷**，只在特定输入规模下才暴露。
- [`docs/DESIGN_DECISIONS.md`](../../blob/centific/docs/DESIGN_DECISIONS.md) ——
  9 条技术决策，每条都写了**放弃了什么**。
- [`demo/`](../../tree/centific/demo) —— 用公开数据重写的架构复现，
  零依赖可以直接跑。调度对照实验能复现出「小任务被大任务饿死」的现象，
  以及优先级调度之后等待时间从 12.54 秒降到 0.77 秒的对照。

最值得一提的一条经验：
**多生产者向同一队列写入时，FIFO 不是公平调度。**
一个 790 段的大任务把队列占满近 90 分钟，
导致一个时段内 79 个小任务全部零进展直至被判超时失败。
修法是 broker 原生优先级队列，代价是大任务晚完成 14%。

## practice 分支里有什么

一套**餐厅经营看板 + 问答服务**：一条线查销售数据库（SQLite），
一条线查公司知识库（BM25 检索），用模型做工具调用把两边拼起来回答。

题方给的是一份能跑但很粗糙的 starter，我按"先加一个会红的测试、再改代码"
的顺序做了 40 多个提交，每一轮都跑同一份 55 题公开题库量分：

| 阶段 | 得分 | 这一轮做了什么 |
|---|---|---|
| 原始 starter | 17 / 100 | 基线，没改任何代码 |
| 中途 | 50 → 63 → 72 → 90 → 98 | 口径重做、安全闸门、版本择优…… |
| 收尾 | 94 → 97 | 修两次"修 A 坏 B"的回归，靠逐题 diff 定位 |
| 最后两轮 | **85 / 90.5**（同一份代码） | 失分题每轮都不一样 → 判定为服务端波动，没当成回归 |

**值得看的四个文件**：

- [`DEBUG_LOG.md`](../../blob/practice/DEBUG_LOG.md) ——
  **18 个缺陷**逐个写"现象 → 假设 → 验证 → 根因 → 修复 → 回归测试"。
  里面有两次**自己改出来的回归**（98 → 94 → 92），包括为什么
  "给上一轮答案里的数字放行"这件事必须做，否则多轮追问会被整句删空。
- [`EVAL_REPORT.md`](../../blob/practice/EVAL_REPORT.md) ——
  逐轮总分、分类得分、每轮失分题。最后三道失分题分别定性为
  "真缺陷 / 部分缺陷 / 模型输出波动"，波动那条给了 6 次复现的逐次结果；
  末尾单独一节拆解"同一份代码连跑两轮差 5.5 分"为什么不是自己的问题
  （失分题每轮不一样 + 分类复测 + 延迟对比）。
- [`README.md`](../../blob/practice/README.md) ——
  跑起来的 3 步命令，以及知识库口径上的取舍（净营业额、订单去重、闭区间、
  预估不计入、新旧版本冲突时以数据库为准……）。
- [`AI_USAGE.md`](../../blob/practice/AI_USAGE.md) ——
  用 AI 辅助写代码的三个实例，每个都写了 **AI 给错诊断、我核实后驳回**的经过。

`eval/llm_gateway.py preflight` 的 14 项接入预检全部通过（输出贴在
[`LLM_SETUP.md`](../../blob/practice/LLM_SETUP.md) 第 7 节）。

反过拟合的一点：代码里搜不到任何题号、期望数字或答案，
公开题库的分数没有靠特判堆出来。

## 技术方向

**大模型应用工程**
LLM 应用流水线设计 · Prompt 版本管理与运行时版本锁定 ·
结构化输出契约 · 上下文窗口构造与 token 成本权衡 ·
模型输出的确定性校验（格式保真、约束检查）

**分布式与可靠性**
多队列解耦 · 优先级调度 · 幂等设计 · 事务边界 ·
失败重试与死信处理 · 弹性伸缩 · 长连接自愈

**检索与 Agent**
RAG 混合检索与重排 · 多智能体协作拓扑 · 分层记忆 ·
Human-in-the-loop 与输出约束

**工程素养**
文档驱动（决策记录 / 事故复盘 / 上线检查清单）·
量化的权衡判断（每项优化都给出代价，而不只给收益）
