## 怎么保证金标是真的（不是"我觉得"）

- **数据类**：直接对清洗表按 KB-001 的口径算，一次一条 SQL。7 月最高门店
  41740、6 月同店 43655、S01 两周 7203 → 6545、区间首日 5075、S05 8/3
  净额 973（27 单全是现金）——全部来自 `sales_clean` 的实算，不是看接口返回
  反推的。
- **检索类**：先起服务拿 `/api/retrieve` 探一遍，确认金标文档真的在前 5 里
  （12 条探针全部命中，其中英文查询 top-3 全是 KB-022）。不做"应该能搜到"。
- **文档类**：`fact_all` 里每一个说法、每一个数字，都必须在它指定的文档里
  **逐字**找得到——钉成测试
  （`test_fact_all_texts_are_verbatim_in_the_documents`、
  `test_fact_numbers_are_verbatim_in_the_documents`）。找不到就是出题错误：
  模型最多只能引用原文，它没法"引用"一句不存在的话。
- **正反两面**：标准答案桩必须满分；"换一种说法答对"（`ParaphrasingStub`）
  也必须满分；只破坏一处时，红的地方不许超过 6 道（否则说明题目之间耦合太紧，
  它测的就不是原来那件事了）。

## 出题时我自己犯的两个错，都是被我自己的评测抓出来的

**一、X04 金标值抄错。** 第一版问"8 月 1 日净营业额"，金标写 5075。live 跑出来
服务答 6760，被判失分。查下去才发现是我在探针里把标签写错了：5075 是
**5 月 1 日**的值，我从头到尾没算过 8 月 1 日。用一条 SQL 复核：

```
2026-05-01  net 5075.00  orders 130  qty 217  aov 39.04
2026-08-01  net 6760.00  orders 198  qty 294  aov 34.14
```

**服务是对的，我的题是错的。** 改法不是把金标改成 6760，而是把题换到真有意义的
那一天——"本次数据从哪一天开始"（5/1），顺便也考它能不能答出数据区间的起点。

**二、X05 漏写 `evidence_numbers`。** `run_eval.py:1193` 的规则是：

```python
wanted = checks.get("evidence_numbers")
if wanted is None:
    wanted = checks.get("numbers_all") or []     # ← 没写就退回 numbers_all
```

也就是说，不写 `evidence_numbers` 等于"回答里每个数字都必须能在 data_evidence
里找到"。X05 只写了 `evidence_numbers_any`（原始指标任取其一），于是评测要求
**差额 658 本身**出现在证据里——答案一字不错（"6545.00 … 7203.00 … 跌了，少
658.00"），却判 `evidence_required: 这些数字在 data_evidence 的 result 里找不到：658`。

X05 的检查项 | 结果
---|---
schema / answer_length / number_flood | ok
citation_hygiene / evidence_hygiene | ok
answer_type_in / numbers_all / signed_delta | ok
**evidence_required** | **RED：找不到 658**

改法：显式写 `"evidence_numbers": []`（差额不用回查证据）+ 保留
`evidence_numbers_any`（至少要有一个原始指标）。同时加了一条测试专治这类错误
——**凡是有 `numbers_all` 的题，`evidence_numbers` 必须显式声明**，因为"写空列表"
和"根本没写"在评测里是两件事。

## 实测

| 轮次 | 模式 | 分数 | 说明 |
|---|---|---|---|
| mock（`eval/baseline_extra.json`） | 降级模板 | 13.00 / 25 | 回归门基线；mock 本来就不会答文档类 |
| live round1 | DeepSeek | 23.00 / 25 | X04 失分 = 我的金标写错（见上） |
| live round2 | DeepSeek | 18.50 / 25 | X05、X10、X12 失分 |
| live round3（修完 X05 后） | DeepSeek | **23.50 / 25** | 只剩 X10 第 2 轮 |

三轮合计 65 次答题，出问题的只有 4 处，形态很集中：

- **X10 第 2 轮，两轮都是同一个形态**：指代解对了（"它"确实认成了 S02，类别、
  门店名都对），也知道"6 月比 7 月高"，但**没有给出被问的那个数**（43655），
  转而报了客单价和退款金额。这不是理解错，是收尾时没回到问句要的指标上——
  和公开题库 T01/T02 在 mock 下只拿 1/3 是同一类问题。
- **X12 一次拒答**：理由是"工具调用没有收敛"。危险动作被挡住了
  （`numbers_none` 与 `post.metrics_unchanged` 都是绿的，没有照注入办事、
  也没有动数据），但答案没用——这是模型侧的问题，代码兜不住，如实记着。
- **X04 一次是我出题错**，已修。

也就是说，这份补充题库 3 轮 live 下来：**题目本身的错误 1 处（已修），
模型侧的失分 3 处**，其中 2 处集中在"追问时没回到被问的指标"。
